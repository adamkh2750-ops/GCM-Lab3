הנדסת תוכנה · Lab 3 · המשך למטלות 1–2

מה צריך להתקין
ואיך מתחילים

הפתרון ממשיך את ענף lab2 במאגר הקיים. לפי הפרויקט, סביבת העבודה היא JDK 25 ו־JavaFX בגרסה 21.0.6. אין צורך בהתקנה מיוחדת עבור חוטים, סנכרון או תורים.

במחשב של אדם, IntelliJ זיהה את JDK 25 ואת Git, ומסך ההתחברות של מטלה 3 נפתח בהצלחה. שלב 9 מסביר איך לפרסם את הגרסה שנבדקה בחשבון שלו.

שלב 1 — חילוץ ופתיחת הפרויקט

  1. מורידים את קובץ הפרויקט למחשב, לוחצים עליו בלחצן ימני ובוחרים Extract All.
  2. פותחים את IntelliJ ובוחרים File → Open.
  3. בוחרים את תיקיית GCM-Labs שחולצה, או את pom.xml שבתוכה, ופותחים כפרויקט.
  4. בתיקיית הפרויקט צריכים להופיע pom.xml, תיקיית src ו־users.txt. שומרים את פרויקט המטלה הישנה בתיקייה נפרדת.

הגדרות והרצה ראשונה

שלב 2 — בדיקת JDK

  1. בתפריט העליון: File → Project Structure → Project.
  2. בשדה SDK בוחרים JDK בגרסה 25.
  3. אם אין גרסה 25: בוחרים Add SDK → Download JDK, מסמנים גרסה 25, מורידים ומאשרים. במחשב Windows עם מעבד Intel/AMD בוחרים חבילת x64 אם נשאלים.
  4. לוחצים Apply → OK. אם מריצים באמצעות Maven, בודקים גם ש־Maven Runner משתמש ב־Project JDK.

שלב 3 — טעינת הספריות

פותחים View → Tool Windows → Maven ולוחצים על Reload All Maven Projects או על סמל הרענון. בהפעלה הראשונה דרוש אינטרנט. ממתינים לסיום ההורדות וה־Indexing.

שלב 4 — בחירת נקודת ההתחלה

בתיקיות הפרויקט פותחים src/main/java/com/example/gcm/Launcher.java. לוחצים בלחצן ימני בתוך הקובץ ובוחרים Run 'Launcher.main()'. אם מופיעה תצורת Lab3 מוכנה, אפשר לבחור בה.

שלב 5 — הכנסת הארגומנטים

  1. פותחים Run → Edit Configurations ובוחרים Lab3 או Launcher.
  2. בשדה Program arguments כותבים 3 10. אם השדה מוסתר, מחפשים אותו תחת Modify options.
  3. השדה Working directory צריך להצביע לתיקייה שבה נמצאים pom.xml ו־users.txt.
  4. מאשרים ומריצים. שני המספרים הם: n=3 כשלונות עד חסימה, t=10 שניות חסימה. מזינים אותם ב־Program arguments, ולא ב־VM options.

אם הארגומנטים חסרים או שגויים, חלון ההתחברות עדיין לא נפתח. בחלונית Run בתחתית IntelliJ לוחצים באזור הקונסולה, מקלידים 3 10 ולוחצים Enter. התוכנית תבקש שוב עד שהקלט תקין.

נתוני התחברות תקינים מתוך קובץ הדוגמה

username: hello@world.net
password: 01041972^H

שלב 6 — בדיקה בין שני חלונות

לוחצים Open another login window. טועים פעם בחלון הראשון ופעם בשני עם אותו אימייל: המונה משותף. לאחר חסימה, גם סיסמה נכונה בחלון השני נדחית. אלו חלונות של אותו תהליך; שתי הפעלות נפרדות מחזיקות זיכרון נפרד, בהתאם לדרישת השמירה בזיכרון בלבד.

במהלך חסימה אפשר לשנות את האימייל כדי לנסות חשבון אחר. שינוי הטקסט אינו מסיר את החסימה של החשבון הקודם. סגירת אחד החלונות מסיימת את כל חלונות התוכנית.

שלב 7 — בדיקת 20 החוטים

לוחצים Run synchronization test (20 threads). הבדיקה משתמשת במצב בדיקה נפרד עם n=10000, כדי לא לשנות את החסימה של המשתמשים האמיתיים. התוצאה המצופה:

After parallel work: 9980 (expected 9980)
After 19 more: 9999; blocked=false
After the 20th: 10000; blocked=true
PASS: no lost updates; exact blocking threshold.

צילומי המסך הנדרשים להגשה

  1. ארגומנטים שגויים והבקשה להזנה ידנית בקונסולה.
  2. התחברות מוצלחת ומסך Welcome.
  3. כשלון עם מספר הניסיונות שנותרו.
  4. חסימה עם ספירה לאחור.
  5. שחרור החסימה והכפתור הזמין.
  6. תוצאת הניסוי עם סנכרון ובלעדיו, וצילום היסטוריית ה־commits.

ניסוי, העלאה והגשה

שלב 8 — השוואה ללא synchronized

צורף סקריפט שמבצע שתי הרצות על עותקים זמניים של הקוד: אחת רגילה ואחת שבה הוסר synchronized מ־UserState. קוד ההגשה המקורי נשאר מסונכרן.

ב־Windows פותחים View → Tool Windows → Terminal, מוודאים שנמצאים בתיקיית הפרויקט ומריצים:

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\compare-synchronization.ps1 -BlockSeconds 10

אם הסקריפט מבקש JDK, מעתיקים את הנתיב מ־Project Structure → SDKs. אם הגרסה ללא סנכרון עוברת, מריצים שוב. איבוד העדכונים תלוי בתזמון החוטים.

שלב 9 — פרסום בחשבון של אדם

שתי הגרסאות של מטלה 3 יוצאות מענף lab2 של אייל, מהקומיט 0e4dd14. את הגרסה שבדקת מפרסמים בחשבון adamkh2750-ops.

  1. ב־GitHub יוצרים מאגר ריק בחשבון שלך. אפשר לקרוא לו GCM-Lab3. משאירים את יצירת README, ‏gitignore ורישיון כבויה. מדף המאגר מעתיקים את כתובת ה־HTTPS.
  2. בטרמינל PowerShell של הפרויקט מריצים את השורה הראשונה, מדביקים את הכתובת כשתתבקש ולוחצים Enter. השורה השנייה מציגה את היעד שהגדרת. 
    git remote set-url origin (Read-Host "Paste your GitHub HTTPS URL")
git remote -v
  3. אחרי שווידאת שהכתובת של origin (push) מכילה את החשבון שלך ואת שם המאגר שבחרת, מעלים את ענף העבודה ואת נקודת המוצא של מטלה 2. 
    git push -u origin lab3
git push origin 0e4dd14:refs/heads/lab2
  4. פותחים את המאגר שלך בדפדפן, בוחרים lab3 ומעתיקים את כתובת הענף לדוח. במאגר פרטי נותנים למרצה גישת קריאה.
